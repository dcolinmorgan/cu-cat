## Change included in this PR

`cu_cat/_gap_encoder.py`, the `H_dict_` annotation on `GapEncoderColumn`, is now a string (`Dict["pyarrow.StringScalar", np.ndarray]`). Annotations in that module are evaluated while the class body runs, and `pyarrow` is `None` when its import fails. The quote is the whole code change. It does not make PyArrow importable on the CI pin: `to_arrow()` on the GPU path still needs a PyArrow that matches numpy. It does make the CPU package importable, which is what the tests need.

## Top 5

### 1. The CI install cannot import the library

`setup.py` puts an upper bound on scikit-learn only inside the `dirty-cat` extra (`setup.py` lines 32-36):

```python
base_extras_light = {
  'dirty-cat': [
    'dirty-cat',
    'scipy',
    'scikit-learn<=1.3.2',]
}
```

`pyarrow>=0.15.0` is a core requirement and is otherwise unpinned. Pip then installs PyArrow 26 (needs numpy 2) and scikit-learn 1.3.2 (keeps numpy at 1.26.4). `DepManager._add_deps` uses a bare `except` and stores nothing (`cu_cat/_dep_manager.py` lines 30-36), so `deps.pyarrow` becomes `None` instead of raising the real ImportError.

Weekly CI has failed on this since 2026-10-11. A GPU runner with `HAS_GPU_RUNNER=true` would get past the guard in this PR and then fail on `Series.to_arrow()`, because PyArrow still does not import.

**Fix.** Drop `scikit-learn<=1.3.2`. The existing suite already passes on scikit-learn 1.9.1. Declare real bounds in `install_requires`: scikit-learn, scipy, and a numpy/pyarrow pair that can import together (numpy>=2 with current PyArrow, or an upper pin on PyArrow if numpy 1.26 must stay). Add a one-line import test so a resolver change fails in CI again. While touching `DepManager`, stop swallowing every exception; an ImportError from a broken binary wheel should surface.

`scikit-learn` and `scipy` are imported while `cu_cat` loads (`_deduplicate.py`, `_gap_encoder.py`, `_table_vectorizer.py`) and are absent from `install_requires`. `pip install cu-cat` on a bare environment fails at import for the same reason.

### 2. `GapEncoder` fits numpy input by row, then `transform` crashes

Reproduced on the CI pin. For

```python
X = np.array([
    ["alpha one", "RIGHT"],
    ["beta two", "RIGHT"],
    ["gamma three", "RIGHT"],
    ["delta four", "RIGHT"],
])
GapEncoder(n_components=2, max_iter=1, hashing=True).fit(X)
```

column 0's dictionary keys were `RIGHT` and `alpha one` (row 0). Column 1's keys were `RIGHT` and `beta two` (row 1). `transform(X)` then raised `AttributeError: 'numpy.ndarray' object has no attribute 'iloc'`.

Two separate mistakes:

`check_input` decides an object is a numpy array with `inspect.getmodule` (`cu_cat/_utils.py` lines 61-84). `getmodule` on an ndarray instance is `None` on both numpy 1.26.4 and 2.5.5 (`ndarray.__module__` is `'numpy'`, but the instance does not expose it). The sklearn `check_array` branch never runs. The dataframe branch tries `.iloc`, swallows the AttributeError, and returns the raw ndarray.

`GapEncoder.fit` then indexes with `X[k]`, and only uses `iloc` if that raises `KeyError` (`cu_cat/_gap_encoder.py` lines 1181-1186). A numpy row slice does not raise. `transform` always uses `X.iloc[:, k]` (line 1286).

The `check_array` call that never runs passes `force_all_finite=False`. scikit-learn 1.9.1 rejects that keyword (`TypeError: check_array() got an unexpected keyword argument 'force_all_finite'`; the replacement is `ensure_all_finite`). Fixing the numpy detection without renaming the argument will break the numpy path on any current scikit-learn.

**Fix.** Detect arrays with `isinstance(X, np.ndarray)`. Call `check_array(..., ensure_all_finite=False)` and pass `force_all_finite` only when `parse_version(sklearn_version) < parse_version("1.6")`. In `fit`, always take columns with `X.iloc[:, k]` for dataframes and `X[:, k]` for arrays. Add a regression test whose dictionary keys are the column uniques, and whose `transform` returns shape `(n_samples, n_components * n_features)`.

### 3. `TableVectorizer` rewrites short strings and crashes on datetimes

`_auto_cast` runs on every object or string column during fit (`cu_cat/_table_vectorizer.py` lines 582-594):

```python
X[i] = X[i].replace("nan", np.nan).fillna("0o0o0")
X[i] = X[i].astype(str).str.rjust(4, "0")
```

That was a workaround for a cuDF n-gram length limit, and it runs on CPU too. Reproduced: a column `["yes", "no", "yes", "no", "yes"]` becomes one-hot features `yesno_0yes` and `yesno_00no`. `"public"` is unchanged because it is already longer than 4 characters, which is why a casual look at `str1_public` still looks right. `test_get_feature_names_out` only checks `len(names) >= len(expected)`, so this passes CI.

The `datetime_transformer` argument is discarded. `__init__` always stores `"passthrough"` (line 488), and `_clone_transformers` assigns `"passthrough"` again (line 543). `DatetimeEncoder` is never wired in. On fit, datetime columns are dropped from the frame that goes to `ColumnTransformer` and then concatenated back with `cudf.concat` (lines 823-844). On CPU `deps.cudf` is `None`. Reproduced with a 4-row frame of one datetime column and one category: `AttributeError: 'NoneType' object has no attribute 'concat'`.

CPU `fit_transform` also does `X.astype(str)` before `ColumnTransformer` (lines 826-827). `transform` does not. Numeric columns survive today only because `StandardScaler` recasts numeric strings. A column that was numeric at fit and mixed at transform will not follow the same path.

**Fix.** Delete the pad-and-fill from the CPU path. If cuDF still needs a minimum string length, pad a copy inside the GPU n-gram call and keep the original values for the one-hot vocabulary. Either honor `datetime_transformer` and default it to `DatetimeEncoder`, or remove the parameter. Concatenate datetime columns with pandas when the frame is pandas. Assert exact feature names in `test_get_feature_names_out`, and add a four-row datetime frame to the CPU tests.

### 4. The GPU fallback paths do not match the CPU path, and one of them drops activations

No device was available, so this is from reading the fit/update code, not from a CUDA run.

**Out-of-memory split keeps the wrong activations.** `_update_block` (`cu_cat/_gap_encoder.py` lines 502-507) recurses on the first half and throws away the returned `H`. It then reads `unq_H[first_half]`, which the recursive call never wrote, and concatenates that stale block with the updated second half. `W` was updated from the discarded `H`. The caller stores the concatenation back into `unq_H`. The test `test_update_block_splits_on_out_of_memory` checks the output shape and that a wide block was attempted. It does not compare values to an unsplit update.

**`engine="sklearn"` is unreachable when RAPIDS imported.** `resolve_engine` (`cu_cat/_gap_encoder.py` lines 124-152) returns `"cuml"` only when cudf is present and the request is `auto`/`cuml`, and returns `"sklearn"` only when cudf is **absent**. An explicit `engine="sklearn"` with cudf installed falls through to `ValueError`. A partial RAPIDS install (cudf present, `cupyx` missing) also raises, instead of using the CPU path the README describes.

**Early stopping looks up a module named `cp`.** `_fit_topics` uses `deps.cp` (line 613). `DepManager` imports the attribute name, so that is `import cp`, which fails and is swallowed. The cupy norm branch never runs. The numpy branch then sees cupy arrays whenever the fit actually stayed on device.

**Transform does more E-step iterations when it chunks.** The in-memory transform calls `_multiplicative_update_h_smallfast` with `self.max_iter_e_step` (default 20). The chunked branch hardcodes `max_iter=100` (line 873). Large inputs (the ones that chunk) are not the same encoder as small inputs.

**Constructor side effects break `get_params`.** `GapEncoder.__init__` stores `engine_resolved[0]`, so `GapEncoder(engine="auto").get_params()["engine"]` is `"sklearn"` on this CPU machine (confirmed). `GapEncoderColumn.__init__` replaces `random_state` with a `numpy.random.RandomState`. sklearn clones and grid search will not round-trip the user's arguments. Upstream skrub removed `tol` / `min_iter` and stopped doing this work in `__init__`.

Also at import, when cupy is present: `cp.get_default_memory_pool().set_limit(size=get_gpu_memory()[0] ** 3)` (line 57). `nvidia-smi` returns free memory in MiB. Cubing that is not a byte cap. 4 MiB free becomes a 64-byte pool; 8000 MiB free becomes a cap far above the device.

**Fix.** In `_update_block`, concatenate the two returned arrays (`first = self._update_block(...); second = self._update_block(...); return xp.concatenate([first, second])`). Extend the existing monkeypatch test to compare against a run that does not raise. In `resolve_engine`, honor `engine="sklearn"` whenever it is requested, and fall back to it when cupy or cupyx failed. Replace `deps.cp` with `deps.cupy`. Use `max_iter_e_step` in both transform branches. Move `check_random_state` and engine resolution into `fit`. Set the pool limit to `mib * 1024 * 1024`, or stop setting it.

### 5. The tests that pass do not cover the failures above

29 passed is a real result, and it is a weak one.

- `bin/test-core.sh` never collects `test_deduplicate.py` or `test_utils.py`. Those files pass, but CI does not run them.
- Nothing instantiates `DatetimeEncoder`. Its docstring example (`fit` on a list of dates) raises `AttributeError: 'list' object has no attribute 'shape'`. `transform` calls `date_series.to_pandas()` (`cu_cat/_datetime_encoder.py` line 141). On CPU the module aliases `cudf = pandas`, and a pandas `Series` has no `to_pandas`, so a datetime column with a missing value raises. `transform` also does `X.fillna(1500000)` (line 258) before extracting parts.
- `test_check_fitted_gap_encoder` is named for the not-fitted error, and the `pytest.raises(NotFittedError)` body is commented out (`cu_cat/tests/test_gap_encoder.py` lines 171-172). Calling `transform` before `fit` is untested.
- Feature-name assertions compare lengths, so finding 3 is invisible.
- The four dirty-cat comparisons are the only tests that look at another encoder, they download external CSVs, they assert `cu_cat` is faster than dirty-cat (timing as a correctness check), and they are skipped on the pandas CI actually installs.
- `cu_cat/tests/utils.py` line 69: `isinstance(type(transformer1), type(transformer2))` is false for two instances of the same class, so `transformers_equal` returns false immediately. `type_equality` in `test_table_vectorizer.py` lines 40-44 treats every object as equal because `isinstance(x, object)` is always true. Neither helper is what the passing tests rely on, which is why they have not failed.
- `codecov.yml` is unused. `ci.yml` never uploads coverage. `test-docs` prints that the doc build is disabled and exits 0 (`.github/workflows/ci.yml` lines 163-165). `test-rapids` is skipped unless the repo variable `HAS_GPU_RUNNER` is set, which is an honest skip, and it means no GPU test has run on GitHub.

**Fix.** Make `bin/test-core.sh` collect `cu_cat/tests` except tests marked as needing the network or a GPU. Add the three regression tests named in findings 2-4. Restore the not-fitted assertion. Compare feature names exactly. Delete or rewrite the dirty-cat speed tests; dirty-cat 0.4.2 is unmaintained and the skip condition already admits it does not run on pandas 2.2+. Vendor a 20-row slice of the midwest survey so those two tests do not depend on OpenML, and treat a 0-byte cached CSV as missing.

## Lower priority

### Divergence from skrub 0.11.0

skrub 0.11.0 requires Python >= 3.11 and scikit-learn >= 1.5.2. This repo requires Python >= 3.10, tests 3.10-3.12, and the extra CI installs pins scikit-learn <= 1.3.2. The fork is not a few patches behind. The public classes diverged in skrub 0.2 and 0.6.

| | skrub 0.11 | cu-cat |
|---|---|---|
| `GapEncoder` input | one column (`Series`). Dataframes are rejected | whole frame, one `GapEncoderColumn` per column |
| default `init` | `"k-means++"` | `"random"` only. The branch that rejected other values is commented out (`_gap_encoder.py` around the `_init_w` gamma draw). `init="k-means"` fits and silently stays random (confirmed) |
| `batch_size` | 1024 | 128 |
| `max_iter_e_step` | 1 | 20 |
| early stopping | `max_no_improvement` | `tol` and `min_iter`, which skrub removed |
| `handle_missing` | removed; missing values become `""` | annotated `Literal["error", "empty_impute"]` with default `"zero_impute"`. The runtime check accepts `"error"` and `"zero_impute"` only. `GapEncoder(handle_missing="empty_impute")` raises `ValueError` (confirmed) |
| `TableVectorizer` high cardinality | `StringEncoder` since 0.6.0 | `GapEncoder(n_components=30)` |
| numeric default | passthrough | `StandardScaler()` |
| datetime default | `DatetimeEncoder` | argument ignored, hardcoded passthrough |
| parameter names | `low_cardinality`, `high_cardinality`, `numeric`, `datetime` (renamed in 0.2.0) | `low_card_cat_transformer`, `high_card_cat_transformer`, `numerical_transformer`, `datetime_transformer` |
| also in skrub, not here | `StringEncoder`, `MinHashEncoder`, `SimilarityEncoder`, `TextEncoder`, `Cleaner`, `TableReport`, polars, `specific_transformers`, `n_jobs` | docstrings still point at `MinHashEncoder` and `SimilarityEncoder` (`_datetime_encoder.py` lines 85-88, `_deduplicate.py` lines 168-171) |

`docs/benchmarks.md` says skrub crashes at about 50k unique strings with `ValueError: NumPy boolean array indexing assignment`. The write-up does not name the skrub version, and it predates `StringEncoder` as the default high-cardinality encoder. Re-measure against skrub 0.11 before citing that crash.

Ken embeddings are still under `cu_cat/datasets/_ken_embeddings.py`. skrub deprecated them in 0.6.2.

**Fix, as a product decision rather than a port.** Keep cu-cat as a GPU `GapEncoder` / `TableVectorizer` and stop claiming parity with skrub, or schedule a real port of `StringEncoder` (the encoder skrub actually defaults to) onto cuML's `TfidfVectorizer` + `TruncatedSVD`. Do not try to replay every skrub 0.2-0.11 commit onto this tree. If the GPU encoder stays multi-column, document that as an intentional difference from `skrub.GapEncoder`.

### Other correctness nits

- `_has_missing_values` (`_table_vectorizer.py` lines 117-123) returns `any(df.isnull())`. On a DataFrame, `any()` iterates column labels, which are truthy, so a complete frame reports missing values (confirmed on a 2x2 float frame). The imputation branch that consults it only fires for `OneHotEncoder` on scikit-learn < 0.24, so current fits do not impute because of this. It will mis-fire if that condition is ever widened.
- `_get_H` (`_gap_encoder.py` lines 340-348) swallows a missing dictionary key and leaves that row as uninitialized `np.empty` memory.
- `deduplicate` is annotated `-> List[str]` and returns a `Series` (`_deduplicate.py` line 231). The docstring says `n_clusters=None` picks the **lowest** silhouette score; `_guess_clusters` uses `np.argmax` (line 79). The example does `from cu_cat.datasets import make_deduplication_data`, and there is no `cu_cat/datasets/__init__.py`. That import raises `ImportError` (confirmed). The tests import `cu_cat.datasets._generating` instead.
- `compute_ngram_distance` calls `pdist(encoded.todense())`, so dedup materializes a dense TF-IDF matrix on the host. The module docstring is right that this stays on CPU; the memory cost is still the thing that will fall over first.
- `cu_cat/__init__.py` lists `TableVectorizer` twice in `__all__`. `check_dependencies` is commented out. The helper it would call imports `importlib.resources` as `pkg_resources` and then uses `pkg_resources.Environment()`, which that module does not have.

### Performance

The in-memory multiplicative update is the right shape (one GEMM-style step, not a Python loop over rows). What is still host-side:

- `_get_H` walks every row in Python to gather activations out of a dict keyed by pyarrow scalars on GPU and by Python strings on CPU. That gather is on the transform return path.
- `get_feature_names_out` builds a fresh `CountVectorizer`, pulls every key through `.as_py()` on GPU, and runs `transform` on the vocabulary.
- `DatetimeEncoder._extract_from_date` round-trips each field through pandas.
- `_fit_topics` calls `nvidia-smi` via `get_gpu_memory()` whenever `deps.cuml` is truthy, including when the engine is sklearn.
- Dedup densifies TF-IDF, as above.

Measure `_get_H` before rewriting the GPU matmul. The notes in `AGENTS.md` match the code: the last bottlenecks were Python loops while the device sat idle.

### Packaging, CI, docs

- No `pyproject.toml`. `setup.py` plus vendored `versioneer.py`. Editable installs already warn that versioneer' s `build_py` does not fit setuptools' editable path (`FileNotFoundError` on a temporary `_version.py` in the 2026-11-22 log). The wheel still built.
- `mypy` is pinned `>=1.19,<1.20` and `pandas-stubs<2.2` so that existing annotations keep passing. `mypy.ini` sets `ignore_missing_imports` for pandas, numpy, and sklearn, so the typecheck CI step is not checking those calls.
- Publish workflow (`.github/workflows/publish-pypi.yml`) uploads with a long-lived `CUCAT_PYPI` token. `permissions: id-token: write` is not set. A commit message on history mentions trusted publishing; the file on `master` does not use it.
- CodeQL workflow uses `actions/checkout@v2` and `github/codeql-action/init@v1`. Those major versions are not on the runner image GitHub documents for current Actions. No CodeQL run appeared in the latest 15 workflow runs.
- Read the Docs (`.readthedocs.yaml`) builds on Python 3.8. The package requires `>=3.10`, so that build cannot install it. The `docs` extra pins Sphinx 3.4.3 and `Jinja2<3.1`. `ci.yml`'s `test-docs` job does not build docs.
- README startup snippet calls `pd.DataFrame` without importing pandas, and compares against `dirty_cat`, which this repo already documents as broken on pandas >= 2.2. Several links point at `github.com/graphistry/cu-cat` (the `setup.py` URL does too). This checkout's `origin` is `dcolinmorgan/cu-cat`.
- `cu_cat/datasets/data/*` is gitignored, but a 0-byte CSV is reused forever. `_fetch_openml_dataset` should delete and retry when the CSV is empty. The doubled `openml/openml/openml.org` directory is `fetch_openml` writing its own `openml/` folder under a data directory that is already named `openml`.

## Suggested order of work

1. **Make the CI install consistent.** Remove `scikit-learn<=1.3.2`, declare scikit-learn, scipy, numpy, and pyarrow in `install_requires` as a set that imports, and keep the quoted annotation. Re-run the weekly workflow. This is the only item that makes every other CI signal real.
2. **Fix numpy `GapEncoder` and add the regression test** (finding 2), including `ensure_all_finite`. Small, user-visible, and currently a crash.
3. **Stop rewriting categories; fix the CPU datetime path** (finding 3). Same size of change as (2), and it changes model outputs, so do it with the exact feature-name assertion in the same PR.
4. **Fix `_update_block` and `resolve_engine`** (finding 4). The value-level test can run on CPU with the monkeypatch that already exists. The `engine="sklearn"` branch needs a machine with cudf installed, or a unit test that stubs `deps.cudf`.
5. **Widen `bin/test-core.sh` and drop the permanently skipped dirty-cat speed tests** (finding 5). Do this after (2) and (3) so the new assertions land with the fixes.
6. **Decide the skrub relationship** and rewrite the README around that decision: GPU `GapEncoder` for high cardinality, not a drop-in skrub, and not a dirty-cat benchmark. Re-run `docs/benchmarks.md` against skrub 0.11 `StringEncoder` and `GapEncoder` separately.
7. **Docs and workflow cleanup:** Read the Docs on Python 3.11+, replace the no-op doc job with a real Sphinx build or delete it, move CodeQL to current actions, switch PyPI to trusted publishing.
8. **Profile `_get_H` on a GPU** before any further matmul work. The chunking and `partial_fit` path is already the right response to the `n_unique * hashing_n_features` allocation described in `AGENTS.md`.
